## Project Overview

A web app that displays real-time lightning strike data on a 3D globe, plus a dedicated "showcase" page where a single lightning bolt is rendered in high detail alongside its mathematical formulas. The lightning simulation should honor real physics (Dielectric Breakdown Model). The same simulation engine serves both views at different detail levels.

**Three pages:**
- `/` - Globe with live lightning data (react-globe.gl)
- `/lightning` - Showcase: high-detail bolt + math formulas (react-three-fiber)
- `/bibliography` - Research sources

**Tech stack:** React 19, TypeScript, Three.js 0.176, @react-three/fiber, @react-three/drei, Vite, Tailwind CSS, react-globe.gl. Server: Node.js + ws.

- Physics/rendering directory split (latest commit)

### What's Broken / Needs Replacement
- **Simulation**: Random walk, not physics-based. Branching is random, not field-emergent. Non-deterministic (uses Math.random()). Unbounded memory in field cache.
- **Rendering**: Geometry recreated every frame. LineBasicMaterial has no width in WebGL. No glow/bloom. Materials cloned per frame. PointLight for flash is expensive.
- **Timing**: Mixed Date.now() and performance.now() causes desync between bolt and ground glow.
- **Architecture**: Physics stepping mixed into render loop. No pre-computation. Can't run same sim at different detail levels.

## Implementation Phases

### PHASE 1: Simulation Engine
**Goal**: Pure TypeScript module that produces complete bolt geometry before any rendering.
**Dependencies**: None. Start here.
**Ref doc**: `simulation-engine-plan.md` Sections 2-5

**Files to create** (all in `client/src/effects/LightningBoltEffect/simulation/`):

1. **`prng.ts`** - Seeded PRNG (mulberry32). Interface: `createSeededRNG(seed) => { next(), nextInt(max), nextGaussian(), fork() }`. See simulation plan Section 3.5 for complete code.

2. **`noise.ts`** - Seeded 3D Perlin/value noise. Must generate permutation table from seed (NOT Math.random()). Interface: `createNoise3D(seed) => (x, y, z) => number` returning [-1, 1]. See errata Section 3.

3. **`types.ts`** - Core types. Key interfaces:
   - `Vec3 { x, y, z }`
   - `BoltSegment { id, start, end, depth, parentSegmentId, stepIndex, intensity, isMainChannel }`
   - `BoltGeometry { segments, mainChannelIds, totalSteps, connectionStep, bounds }`
   - `SimulationConfig { eta, stepLength, maxSteps, candidateCount, coneHalfAngle, maxBranchDepth, baseBranchProb, branchProbabilityRatio, branchDepthDecay, maxBranchesPerStep, fieldConfig, connectionThreshold, maxSegments }`
   - `FieldConfig { backgroundField, channelInfluence, groundInfluence, epsilon, noiseScale, noiseAmplitude, noiseSeed }`
   - `DetailLevel` enum: GLOBE, SHOWCASE
   - See simulation plan Section 4 for full definitions.

4. **`config.ts`** - Detail level presets. Globe: 80 max steps, 8 candidates, depth 2, 100 max segments. Showcase: 200 max steps, 16 candidates, depth 4, 800 max segments. `createConfig(level, overrides?)` factory. See simulation plan Section 5.

5. **`FieldComputation.ts`** - Distance-based field approximation (NOT Laplace solve). For each candidate point: background field + sum of channel influence (inverse distance to each channel point) + ground proximity + noise. See simulation plan Section 3.1 for code.

6. **`BranchSelection.ts`** - DBM probability: `P(i) = |phi_i|^eta / sum_j(|phi_j|^eta)`. Branching emerges when multiple candidates from same head have competitive probabilities. See simulation plan Section 3.3-3.4 for complete algorithm.

7. **`GrowthStep.ts`** - Single growth step: enumerate candidate directions in a cone around current direction, compute field at each, select via DBM probability, handle branching, check for ground connection. See simulation plan Section 3.2.

8. **`spatial.ts`** - SpatialGrid class for fast nearest-channel-point lookups. Simple 3D grid with cells. Only needed for showcase detail level. See simulation plan Section 5.4.

9. **`BoltSimulator.ts`** - Main entry point. `simulateBolt(input: { start, end, seed, config }) => { geometry, stats }`. Runs the growth loop to completion. Simulation operates in normalized space: start=(0, 0.5, 0), end=(0, -0.5, 0), total distance=1.0. After completion, walks the segment tree to identify the main channel (path that actually reached ground). See simulation plan Section 2.

10. **`index.ts`** - Public exports: `simulateBolt`, types, `createConfig`, `DetailLevel`.

**Validation**: Create a temporary test script. Run `simulateBolt()` with a fixed seed. Verify: (a) deterministic output, (b) 50-200 segments for showcase, (c) main channel connects start to end, (d) branches exist at depth > 0, (e) runs in <16ms for showcase config.

### PHASE 2: Animation Layer
**Goal**: State machine that maps simulation output to time-based animation state.
**Dependencies**: Phase 1 (needs BoltGeometry type).
**Ref doc**: `simulation-engine-plan.md` Section 6, `plan-revisions-and-errata.md` Section 4

**Files to create** (all in `client/src/effects/LightningBoltEffect/animation/`):

1. **`types.ts`** - `AnimationPhase` enum (LEADER_STEPPING, CONNECTION_PAUSE, RETURN_STROKE, STROKE_HOLD, FADING, INTERSTROKE, COMPLETE). `AnimationState { phase, phaseProgress, visibleSegments: Set<number>, segmentBrightness: Map<number, number>, returnStrokePosition, strokeCount }`.

2. **`BoltTimeline.ts`** - Timeline config: leader duration, connection pause, return stroke duration, stroke hold, fade, subsequent strokes count, interstroke interval. Two presets: Globe (fast: 200ms leader, 2 strokes) and Showcase (detailed: 800ms leader, 4 strokes). `createTimeline(geometry, detailLevel)`.

3. **`BoltAnimator.ts`** - Takes BoltGeometry + BoltTimeline. `start(currentTime)`, `update(currentTime) => AnimationState`. Phase logic:
   - **LEADER_STEPPING**: Reveal segments progressively by stepIndex. Recent segments brighter.
   - **CONNECTION_PAUSE**: All leader visible at dim (0.3), brief pause (50ms).
   - **RETURN_STROKE**: Main channel lights up from ground upward. Wavefront at full brightness, passed segments slightly dimmer, branches flash briefly as their parent illuminates.
   - **STROKE_HOLD**: Peak brightness, exponential decay over hold period.
   - **FADING**: All brightness multiplied by (1 - progress). Main channel fades slower.
   - **INTERSTROKE**: Minimal brightness (0.05-0.1), channel "warm" before next stroke.
   - **COMPLETE**: Empty, signals termination.
   - Subsequent strokes: loop RETURN_STROKE > STROKE_HOLD > FADING > INTERSTROKE. Each stroke dimmer (0.8^strokeIndex). See errata Section 4 for all state method details.

4. **`index.ts`** - Exports.

**Validation**: Create BoltAnimator with a known geometry. Call update() at various times. Verify phase transitions happen at correct times, visible segment counts match expectations, brightness values are in [0, 1].

### PHASE 3: Rendering
**Goal**: Efficient renderer that takes AnimationState and draws the bolt using LineSegments2 with actual line width.
**Dependencies**: Phase 1 (types), Phase 2 (AnimationState type).
**Ref doc**: `rendering-performance-plan.md` Sections 1-5, `plan-revisions-and-errata.md` Sections 5-6

**Files to create/modify** (in `client/src/effects/LightningBoltEffect/rendering/`):

1. **`LightningMaterials.ts`** (NEW) - Material pool. Create 5 `LineMaterial` instances at init time (main channel 4px, branch1 3px, branch2 2px, branch3 1.5px, glow 8px additive). `getMaterialForDepth(depth)`. `updateResolution(w, h)` - MUST be called on resize. `updateOpacity(opacity)` for fade. Never clone materials. See rendering plan Section 5.

2. **`BoltRenderer.ts`** (NEW) - Unified renderer. Key responsibilities:
   - `setGeometry(geometry: BoltGeometry, worldStart: Vec3, worldEnd: Vec3)`: Compute world transform (origin, scale, rotation). Serialize BoltSegment[] to flat Float32Array buffers (see errata Section 5 for bridge code). Group segments by depth. Create one `LineSegments2` per depth tier + one for glow. Add all to a THREE.Group.
   - `render(state: AnimationState)`: Update material opacities based on segment brightness. For segments not in `state.visibleSegments`, move vertices off-screen (set to 9999). For visible segments, set opacity from `state.segmentBrightness`. Update glow line opacity.
   - `updateResolution(w, h)`: Forward to materials.
   - `dispose()`: Remove group from scene, dispose geometries (NOT materials - they're pooled).
   - For globe: add a second wider LineSegments2 with additive blending as fake glow.
   - For showcase: just render the lines; bloom handled by post-processing in Phase 6.

3. **Modify `FlashEffect.ts`**: Remove PointLight. Replace with: (a) ambient light intensity bump for showcase, (b) nothing for globe. Keep the ScreenFlashEffect class but make it optional. See rendering plan Section 4.

4. **Modify `rendering/index.ts`**: Export BoltRenderer, LightningMaterials. Keep FlashEffect exports.

**DO NOT modify or delete** `LeaderRenderer.ts` or `StrokeRenderer.ts` yet - they'll be removed in Phase 8.

**Validation**: Create a BoltRenderer in a test scene. Feed it a BoltGeometry and cycle through AnimationStates. Verify: lines appear with actual width, depth tiers have different widths, glow line is visible, opacity animation works, no geometry recreation per frame.

## Key Technical Decisions

1. **DBM, not random walk**: Growth probability `P(i) = |phi_i|^eta / sum_j(|phi_j|^eta)`. eta=2.0 default. Branching emerges from field competition, not random injection.

2. **Distance-based field approximation, not Laplace solve**: `E(r) = E_0 + sum_i(k / |r - r_i|) + k_ground / (y - y_ground) + noise`. Fast enough for real-time.

3. **Pre-compute, then animate**: Simulation runs to completion (sync, <16ms for showcase). Animation reveals the pre-computed geometry over time via shader uniforms. No per-frame physics.

4. **LineSegments2 for actual line width**: From `three/examples/jsm/lines/`. Grouped by depth tier (4 tiers = 4 draw calls per bolt). LineMaterial needs `resolution` updated on resize.

5. **Selective bloom in showcase only**: Via @react-three/postprocessing Selection API. Globe uses fake glow (wider additive line). Auto-disable bloom if frame time exceeds 30ms.

6. **mulberry32 PRNG**: Deterministic, high quality. Same seed = same bolt. Replaces broken LCG.

7. **KaTeX for math**: Faster and lighter than MathJax. Token-based highlighting (not regex).

8. **Context for showcase state, refs for animation values**: React context manages parameters. Mutable refs carry per-frame values (flashIntensity) to avoid React re-renders.

9. **Server stays JS**: No TypeScript build step. Direct WebSocket to Blitzortung replaces Puppeteer (if protocol allows). Demo mode as fallback.
