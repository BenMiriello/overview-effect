# Hotspots Feature Spec

Problem: Hotspots are useful and we use them when present to navigate to the current main hotspot on the map. But we don't provide it as a feature after. If a new hotspot appears we don't give the user the option to go there. We don't let them go back to it if they were already there.

Solution: A hotspot tracking system with a new UI button that can always take them to the top hotspot on the earth at that time. Later modifications might allow taking them to multiple hotspots. But for now just the main one. If it changes, have some little notification animation/alert on/over the button ("Go to the new biggest hotspot" or something like that). This can be a circle icon alongside the 2d/3d button, same size and style, with a fire icon in it. Lucide 'flame' icon. We need the determination of the hotspot area to be... within a certain geographical range containing the hotspot completely or mostly, and ideally in a radial circular shape, or square as a fallback. And we'll measure if we're still 'in' it by if it's in the field of view. If we're in it the icon should be inactive (low opacity icon) and button cursor-default. On hover it can say 'You're already viewing the most active hotspot. Click to re-center." and so we're not advertising it but it'll still work to center over the hotspot. But otherwise it'll look active with cursor-pointer and full opacity icon. icon style should transition change over 0.4s. This all requires storing and tracking hotspots in the backend, updating frontend with them. Something partially already done but not for this system. Design a consistent system that does this reliably and accurately. Use the existing hotspot detection algorithm. Evaluate it for any issues so that we can refine it, but let's just extend it. As for when the hotspot changes - let's have some minimum threshold of how often it can change. Because detecting a hot spot requires watching over time anyways, we don't want this to change unnecessarily often. It wouldn't be bad if we could show them frequent updates, but the issue is that if we are basing it off of a short time span, then we are likely to send them back and forth often, based on just small bursts of activity. We probably would send them there right after it finished.

It's not like we need to be perfectly accurate or overly conservative about waiting to make sure that the hot spot is really active over the course of, like, an hour or anything, but maybe at least a couple of minutes. Let's say a 2-minute range is fair; I think that's what we're already using. A minute minimum, say 10 minutes maximum, but probably 2 minutes.
